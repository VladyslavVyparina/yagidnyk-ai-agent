## Архітектура

```
backend/            Node.js + TypeScript + Express + PostgreSQL (Prisma)
  ├─ ai/            Системний промпт, ядро агента (OpenAI), function calling
  ├─ channels/
  │   ├─ telegram/  Клієнтський бот (Telegraf) + надсилання повідомлень
  │   └─ tiktok/     Вебхук + клієнт для TikTok Business Messaging API
  ├─ services/      Google Sheets, база знань, ліди, нагадування, сповіщення менеджеру
  ├─ admin/         REST API для адмінки (auth, розмови, контакти, база знань, товари)
  └─ messaging/      Єдина точка надсилання повідомлень клієнту незалежно від каналу

admin-frontend/     React + Vite адмінка у стилі SendPulse (список чатів, чат-вікно, картка клієнта)
```

Один і той самий AI-агент (промпт, база знань, прайс) обслуговує обидва канали — Telegram і TikTok,
тому логіка й тон спілкування ідентичні, як і просив замовник.

## Швидкий старт (Docker)

1. Скопіюйте `backend/.env.example` у `backend/.env` і заповніть значення (див. розділи нижче).
2. З кореня проєкту:

```bash
docker compose up --build
```

3. Backend буде доступний на `http://localhost:4000`, адмінка — на `http://localhost:5173`.
4. При першому запуску backend автоматично виконає міграції бази даних та створить адмін-акаунт і
   базові демо-дані (FAQ, приклад товарів) через `npm run seed`.

## Локальна розробка без Docker

Потрібні: Node.js 20+, PostgreSQL 16+.

```bash
cd backend
cp .env.example .env      # заповнити значення
npm install
npm run prisma:migrate:dev
npm run seed
npm run dev                # запускає сервер + Telegram-бота (long polling)
```

```bash
cd admin-frontend
cp .env.example .env
npm install
npm run dev                 # http://localhost:5173
```

## Налаштування Telegram-ботів

Потрібно **два окремих боти** в Telegram:

1. **Клієнтський бот** — той, з яким спілкуються клієнти (заготівельники).
2. **Бот сповіщень** — пише лише в окремий чат/групу Романа, повідомляє про нові ліди й хендофи.

Кроки:

1. У Telegram напишіть [@BotFather](https://t.me/BotFather), команда `/newbot` — отримаєте токен.
   Повторіть для другого бота.
2. Впишіть токени в `backend/.env`:
   - `TELEGRAM_CLIENT_BOT_TOKEN` — токен клієнтського бота.
   - `TELEGRAM_NOTIFY_BOT_TOKEN` — токен бота сповіщень.
3. Створіть групу в Telegram для Романа, додайте туди бота сповіщень адміністратором, напишіть будь-яке
   повідомлення в групу, і дізнайтесь `chat_id` групи (найпростіше — через
   `https://api.telegram.org/bot<TOKEN>/getUpdates`). Впишіть його в `TELEGRAM_NOTIFY_CHAT_ID`.
4. Режим клієнтського бота: `TELEGRAM_CLIENT_BOT_MODE=polling` підходить для старту без публічного
   домену. Для продакшн-навантаження краще `webhook` + `TELEGRAM_WEBHOOK_URL=https://ваш-домен.com`.

## Налаштування Google Таблиці з цінами

Колонки визначаються **автоматично за текстом заголовків**, тому порядок і кількість колонок не
принципові. Розпізнаються (регістр не важливий): `Товар`/`Назва`, `Категорія`, `Ціна`/`Ціна суха`/`Суха`,
`Ціна свіжа`/`Свіжа`, `Приймається`/`Доступність`, `Примітка`/`Сезон`.

Мінімальний робочий варіант — лише дві колонки (як у тестовій таблиці, яку ви вже підключили):

| ТОВАР | ЦІНА |
|---|---|
| Полин | 180 грн |
| Туя | 500 грн |

Розширений варіант (якщо потрібні окремо ціна свіжої/сухої сировини та позначка сезонності):

| Товар | Категорія | Ціна свіжа | Ціна суха | Приймається | Примітка |
|---|---|---|---|---|---|
| Полин | трава | 10 | 50 | так | |
| Гілки сосни | гілки | | | ні | не приймаємо |

За замовчуванням система читає аркуш `Аркуш1`, дані з рядка 3 (`GOOGLE_SHEETS_RANGE=Аркуш1!B3:G1000`),
а заголовок бере автоматично з рядка над діапазоном (рядок 2). Якщо назва аркуша чи діапазон інші —
зміните `GOOGLE_SHEETS_RANGE` у `.env`.

Кроки підключення через Service Account (рекомендовано, не потребує від вас передавати особистий Google-акаунт):

1. Перейдіть у [Google Cloud Console](https://console.cloud.google.com/), створіть проєкт (або
   використайте наявний).
2. Увімкніть **Google Sheets API** для проєкту (APIs & Services → Enable APIs → Google Sheets API).
3. Створіть Service Account (IAM & Admin → Service Accounts → Create Service Account).
4. У створеного Service Account відкрийте вкладку Keys → Add Key → JSON, завантажте файл ключа.
5. З JSON-файлу візьміть `client_email` і `private_key`, впишіть у `.env`:
   - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
   - `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` (весь ключ одним рядком, з `\n` замість переносів рядків)
6. Відкрийте вашу Google Таблицю з прайсом → Доступ (Share) → додайте email сервісного акаунта
   (`...@...iam.gserviceaccount.com`) з правом **Читач (Viewer)**.
7. Скопіюйте ID таблиці з посилання (частина між `/d/` і `/edit`) у `GOOGLE_SHEETS_SPREADSHEET_ID`.
8. За потреби змініть діапазон `GOOGLE_SHEETS_RANGE` (за замовчуванням `Прайс!A2:F1000`) під назву
   вашого аркуша.

Синхронізація відбувається автоматично за розкладом `GOOGLE_SHEETS_SYNC_CRON` (за замовчуванням кожні
15 хвилин), а також вручну через адмінку/ендпоінт `POST /api/products/sync`. Після кожної синхронізації
система перевіряє, чи зʼявились у прайсі товари, якими цікавились клієнти під час несезону — і
автоматично надсилає їм нагадування.

## Підключення TikTok (важливо прочитати)

TikTok має жорсткі офіційні обмеження, які напряму впливають на можливий функціонал:

- **Коментарі**: TikTok не надає жодного публічного API для читання чи відповіді на коментарі. Ця
  функція технічно неможлива легітимним шляхом — тому в системі її немає.
- **Директ (DM)**: працює лише офіційний **TikTok Business Messaging API**, і лише "вхідне" —
  бот може відповідати тільки тим, хто написав першим, з вікном ~48 годин на автоматичні відповіді.
  "Холодні" DM і розсилки заборонені політикою TikTok.

Тому в системі реалізовано: клієнт сам пише боту в TikTok директ (наприклад, за кодовим словом з опису
відео на кшталт "напишіть ЦІНА в директ") → AI-агент Олександр веде діалог так само, як у Telegram.

Кроки отримання доступу (виконує власник TikTok-акаунту):

1. Створіть і верифікуйте **TikTok Business Account**.
2. Зареєструйтесь як розробник у [TikTok for Business Developer Portal](https://business-api.tiktok.com/portal/docs).
3. Подайте заявку на доступ до **Business Messaging API** (потребує підтвердження від TikTok, термін
   розгляду залежить від TikTok).
4. Після схвалення отримаєте `App ID`, `App Secret`, `Access Token` і `Business ID` — впишіть їх у
   `.env` (`TIKTOK_APP_ID`, `TIKTOK_APP_SECRET`, `TIKTOK_ACCESS_TOKEN`, `TIKTOK_BUSINESS_ID`).
5. Налаштуйте вебхук на адресу `https://ваш-домен.com/webhooks/tiktok`, вкажіть
   `TIKTOK_WEBHOOK_VERIFY_TOKEN` (довільний секрет, який TikTok надсилатиме назад для перевірки).
6. Точні назви полів запиту/відповіді TikTok видає в документації порталу після підключення застосунку
   — код клієнта в `backend/src/channels/tiktok/client.ts` побудований за загальноприйнятою структурою
   Business API і, ймовірно, потребуватиме звірки 1-2 назв полів із фінальною документацією, яка
   відкривається лише після апруву. Це буде швидке доопрацювання, коли доступ буде отримано.

До моменту отримання доступу TikTok-канал просто не активний (бот не отримує подій) — решта системи
(Telegram, адмінка, ціни, база знань) працює повністю незалежно від цього.

першому запуску через `.env`, потім їх можна змінити напряму в базі):

```

Пароль: bY8xiQ1vtT5deK2
```

У списку чатів за замовчуванням показуються **лише розмови, де вже була реальна взаємодія** (AI чи
менеджер хоча б раз відповіли клієнту) — порожні/незапущені чати не відображаються, як і просив
замовник.

У кожному чаті адмін бачить картку клієнта (імʼя, нік у Telegram/TikTok, номер телефону — якщо клієнт
його вже надав, він автоматично підтягується в картку, посилання на профіль TikTok, історію відкладених
запитів і лідів), може писати повідомлення, надсилати фото/відео/файл (для TikTok — лише фото/відео,
через обмеження самого TikTok API), і перемикати діалог між AI та ручним режимом менеджера.

## Як працює AI-агент

- Промпт (`backend/src/ai/systemPrompt.ts`) побудований на основі референсу "живого менеджера", який
  ви надали, адаптований під чоловічого персонажа Олександра і українську мову (з розумінням
  російської, але без переходу на неї).
- Ціни AI **ніколи не вигадує** — завжди звертається до функції `get_product_price`, яка бере дані з
  таблиці `Product` (синхронізується з Google Таблиці).
- Питання поза прайсом (умови доставки, пакування тощо) AI шукає через `search_knowledge_base` —
  редагується прямо в адмінці (`База знань`).
- Якщо товару немає в прайсі — AI повідомляє про це чесно і зберігає інтерес клієнта
  (`save_pending_interest`), щоб автоматично нагадати, коли товар зʼявиться.
- Коли запит достатньо кваліфікований і є контакт клієнта — AI викликає `create_lead`, який передає
  розмову менеджеру Роману (сповіщення в окремий Telegram-чат) і переводить статус розмови в
  "Менеджер" — з цього моменту AI більше не відповідає в цій розмові автоматично, поки адмін не
  поверне режим AI назад в адмінці.
